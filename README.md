# Maestro-Herdr-Config

**A terminal environment, rebuildable from a repository**

Every post-install change to this machine's Herdr configuration, captured so
it can be reviewed and restored.

---

Single home for what changes how Herdr behaves on this machine: keybindings,
UI settings, and the plugins installed into it. Nothing here duplicates
Herdr's own state — only the configuration a person deliberately set.

## Scope

Config only, never runtime state.

| Captured | Not captured |
| --- | --- |
| `config/config.toml` — keybindings, UI, worktrees, sound | `session.json` — live workspace/tab/pane topology |
| `plugins.md` — installed plugins, source, pinned commit | `plugins.json` machine-specific paths, fetched plugin binaries |
| `integrations.md` — the Pi lifecycle integration and its version | server/client logs, `herdr.sock` / `herdr-client.sock` |

Herdr's own `~/.config/herdr/` directory holds all of the excluded items;
they are regenerated by the running server and are not meaningful outside
this machine.

## Layout

```text
config/         captured config.toml
plugins.md      installed plugins: id, source, pinned commit, install command
integrations.md the Pi lifecycle integration and its version
```

## Restore

1. Install Herdr (see [herdr.dev](https://herdr.dev)).
2. Copy `config/config.toml` to `~/.config/herdr/config.toml`.
3. Run each install command listed in [plugins.md](./plugins.md).
4. Start Herdr; the Pi integration installs itself into a Pi session's
   extensions the first time a Pi agent runs inside a Herdr pane (see
   [integrations.md](./integrations.md)).

## Related

Pi-side extensions — including the managed Herdr integration itself and any
custom hooks placed beside it — are captured by
[maestro-pi-config](https://github.com/maestrolabs-hq/maestro-pi-config), not
here. This repository owns only Herdr's own configuration and plugins.
